# Deep Dive: The Model Swap That Broke Into OpenAI

Three researchers at the security startup Hacktron AI set out to test whether
an AI coding agent could find and chain real vulnerabilities against a live
target — OpenAI's own community forum. Using Claude as the driving agent,
they identified a heap-buffer-overflow remote-code-execution bug in the
Discourse forum software (CVE-2026-32882, triggered through malformed
HEIC/HEIF image uploads that bypassed format checks), then chained it with an
SSO token-theft flaw to reach OpenAI staff ChatGPT/Codex sessions and an
internal code repository.

The detail that makes this more than another bug-bounty writeup: the exact
same attack attempt did not work when the researchers' agent was running on
Claude Opus 4.8. It worked within hours once they swapped in Claude Opus 5 —
same team, same target, same exploit chain, one model upgrade. This episode
walks through how the exploit actually worked, why a controlled before/after
test like this is a rare, concrete way to observe a capability threshold
being crossed in real time (rather than inferring it from a benchmark
score), how OpenAI responded (a patch in roughly 14 hours and a $6,500
bounty), and what this does and doesn't tell us about dual-use risk as
frontier models get better at offensive security.
